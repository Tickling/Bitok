# «Биток» как франшиза: как устроить настройку школ

Ветка: `main2_франшиза`. Подписки «Биток Про» в этой ветке нет — всё, что было в ней, доступно ученикам бесплатно.
Деньги франшиза зарабатывает на школах (абонентская плата или процент с оплат тренировок), а не на учениках.

## Рекомендация в одну строку

**Настройка школы — в веб-кабинете на сайте, быстрые ежедневные действия — в приложении.**
Одно общее приложение «Биток» в сторах; школа выбирается по ссылке-приглашению или QR-коду,
и приложение перекрашивается под неё. Отдельные сборки «под бренд» — платная опция для крупных сетей.

## Почему не всё в приложении и не всё на сайте

| Что настраивается | Где удобнее | Почему |
|---|---|---|
| Бренд: название, логотип, цвета | Веб-кабинет | Загрузка логотипа, предпросмотр на телефоне и планшете, делается один раз |
| Тренеры школы, роли, доступы | Веб-кабинет | Приглашения по номеру, права «владелец / администратор / тренер» |
| Клубы, столы, адреса, часы работы | Веб-кабинет + приложение | Создать — на сайте; «закрыть стол на сегодня» — в приложении |
| Цены, абонементы, скидки | Веб-кабинет | Таблицы, массовые правки, история изменений |
| Приём оплаты (ЮKassa, CloudPayments, Т-Банк) | Только веб-кабинет | Договор и ключи магазина вводятся на сайте; в приложение ключи не попадают |
| Магазин: товары и услуги | Оба | Каталог и импорт — на сайте; «сфотографировал и выложил» — в приложении |
| Упражнения и методички | Оба | PDF-импорт и библиотека — на сайте (большой экран); схема, точка удара, видео-урок — и там, и в приложении |
| Расписание, заявки, оценки тренировок | Приложение | Это ежедневная работа тренера в клубе |

## Как это устроено технически

```
Ученик / тренер ──► приложение «Биток» ──► API ──► данные школы (tenant)
Владелец школы  ──► веб-кабинет cabinet.bitok… ─┘
```

1. **Школа = tenant.** У каждой записи (тренер, клуб, слот, бронь, упражнение, товар, платёж) есть `schoolId`.
   Ученик может состоять в нескольких школах — переключатель в профиле.
2. **Конфигурация школы** — один документ, который приложение загружает при входе и кэширует:
   ```json
   {
     "schoolId": "flagman",
     "name": "Школа бильярда «Флагман»",
     "brand": { "accent": "#7A1C2B", "accentSecondary": "#157A71", "logoUrl": "…", "appIcon": "oxblood" },
     "features": { "shop": true, "groupTraining": true, "camera": true, "gifts": false },
     "payments": { "provider": "yookassa", "mode": "prepay" },
     "booking": { "minLeadMinutes": 120, "maxHoursInRow": 3, "cancelHours": 12 },
     "contacts": { "vk": "https://vk.com/…", "phone": "+7 …" }
   }
   ```
   В приложении это ложится на то, что уже есть: темы и альтернативные иконки (`DesignSystem`), клубы (`DemoVenue`),
   тренеры, магазин (`DemoListing`), упражнения (`customExercises`).
3. **Вход в школу:** ссылка `https://bitok…/s/flagman` или QR в клубе → открывает приложение (Universal Links / App Links)
   → выбирается школа → вход по номеру телефона. Без ссылки — поиск школы по городу.
4. **Оплата — на счёт школы.** Каждая школа подключает свой магазин у провайдера; франшиза получает свою долю через
   сплитование платежей (ЮKassa «Безопасная сделка»/сплит, CloudPayments Marketplace) или ежемесячный счёт.
   Секретные ключи хранятся только на сервере.
5. **Обновления без релиза:** всё, что меняется в веб-кабинете (цвета, тренеры, цены, упражнения, товары),
   приходит в приложение при следующем открытии. Новый релиз в сторах нужен только для новых функций.

## Что сделать по шагам

1. **Бэкенд с tenant-моделью** (в репозитории уже есть заготовки `backend/` и API-контракты): школы, роли, конфигурация,
   загрузка файлов (логотипы, фото, видео-уроки), платежи.
2. **Веб-кабинет школы** (отдельный сайт): бренд с живым предпросмотром экрана приложения, тренеры, клубы,
   цены, оплата, магазин, библиотека упражнений, заявки с лендинга.
3. **Приложение:** загрузка конфигурации школы вместо демо-данных, переключатель школ, вход по ссылке-приглашению.
4. **Лендинг** (`site/`) уже готов: заявки учеников и тренеров; позже — форма на API вместо копирования текста.
5. **White-label по запросу:** отдельная сборка с иконкой и названием школы для сетей от N клубов.

## Открытые вопросы к владельцу

- Модель дохода франшизы: фикс в месяц, процент с оплат или смешанная.
- Кто проверяет новые школы перед публикацией (модерация).
- Нужен ли общий каталог тренеров между школами (ученик ищет тренера по городу).
